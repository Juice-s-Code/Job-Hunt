# Continue an existing job hunt

Use the owner's current tracker as the source of truth until reconciliation is
complete. Do not run `init` over it, import another person's vault, or copy private
Git history into the public toolkit. This is a review procedure, not an automatic
migration command. A new CLI vault can sit beside an old private tracker.

## Inventory before writing

Ask which tracker, documents, accounts and prior outcomes belong to this owner
and are authorized to read. Inspect instructions/handoffs and dirty files. Find
active browser tasks and ambiguous submissions. Preserve current holds before
starting another form. Agree on the new private path and migration scope.

Record exact employer, ATS, job/requisition ID, canonical URL, observed status,
receipt/evidence location, actual attachment hashes where known, submission time,
and provenance. Preserve employer aliases and office mirrors. Keep unknowns unknown.
An old checkbox, resume file, click log or absent email is insufficient proof.

## Choose how to continue

**Existing system retained:** Codex can follow this toolkit's research/document/
alert playbooks while writing findings into the owner's existing private tracker.
Use that system's own claims and receipt controls. Do not claim its data has been
reconciled by this CLI, or run CLI commands against incompatible state.

**New CLI vault for future work:** initialize a separate empty approved vault,
complete the profile and record legacy applications/holds in private
`Research/Legacy Application Register.md`. Before every new claim, manually check
that register plus the old tracker and employer records. The CLI's dedupe covers
only its own imported inventory; it does not automatically enforce the legacy list.
Retain the old system as the historical record.

There is no safe bulk historical receipt import in this version. Do not replay
old jobs through `claim`/`receipt` with synthetic evidence to manufacture history,
and do not add legacy counts to the CLI ledger. Report separate reconciled legacy
and new CLI counts, with overlap/unknowns stated, until a reviewed migration tool
exists. An existing pending/uncertain application remains held in the old system.

## Reconcile and hand off

Resolve identities, receipt-backed counts, duplicate mirrors and outstanding
owner decisions. With owner-authorized read access, verify portal/inbox evidence;
failed authentication is unknown, not cleared. Record discrepancies and the exact
next safe action. Do not send a retry to test whether an application exists.

Preserve the old files unchanged, document which system owns new work, and leave
an explicit private handoff. Continuing a search never requires copying private
content into this public repository or giving a friend access to another vault.
